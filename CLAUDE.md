# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

The frontend is a single self-contained file: [index.html](index.html). It is "Trading Terminal" (renamed from "Market Terminal", itself renamed from "Trading Desk" — the tagline "Trade Like a Lion" and an inline SVG lion mark on the login screen were added purely cosmetically this round, no functional change), a web app for logging trades, defining a personal trading playbook, tracking capital/leverage exposure, reading a live market-regime dashboard with charts, screening the NIFTY 500 universe, and getting a position-sizing sanity check — backed by Supabase (Postgres + Auth) for storage/login and three Vercel serverless functions (`api/regime.js`, `api/breadth.js`, `api/news.js`) for live market/news data. There is no build system for the frontend, no test suite — all HTML/CSS/JS lives inline in `index.html`. Other files: `nifty500.json` (static NIFTY 500 constituent list for the Journal's instrument autocomplete, refreshed manually/quarterly), `sectors.json` (static sector-name → constituent-symbols map for 14 confirmed NSE sector indices, same manual-refresh convention — feeds the Sector Strength panel's RS Rating drill-down and its %-above-200-EMA fallback; the panel's primary live number now comes straight from `api/regime.js`, see below), `marketcap.json` (static symbol → `Large Cap`/`Mid Cap`/`Small Cap` map, added this round for the Stocks tab — built from NSE's own NIFTY 100/Midcap 150/Smallcap 250 constituent lists, which exactly partition the NIFTY 500; same manual-refresh convention), `fo_universe.json` (static, best-effort list of F&O-eligible symbols — no live-verifiable NSE source found for this one, compiled from general knowledge, badges the Sector Strength drill-down's F&O names), `scripts/backfill_ema.py` + its committed output `scripts/ema_backfill_*.json` (one-time offline EMA-breadth computation, not run automatically), `scripts/backfill_nifty500_ema20.py` + `scripts/nifty500_ema20_*.json` (same idea, one series — the NIFTY 500 index's own 20-EMA), `supabase/schema.sql` (fresh-install DB baseline) + `supabase/migration_*.sql` (incremental, additive changes actually run against the live project — run by hand in the Supabase SQL Editor), `package.json` (pins `engines.node` for Vercel's build of the `api/` functions — no dependencies), and two skills: `.claude/skills/supabase-backend/SKILL.md` (Supabase/RLS/auth conventions — read before touching auth or adding a table) and `.claude/skills/nse-market-data/SKILL.md` (which NSE endpoints actually work, the regime-scoring/EMA-breadth/position-sizing formulas — read before touching either `api/*.js` function or the Market Regime tab).

Deployed on Vercel, auto-deploying from `main` on `github.com/jainarham32-creator/trading`. Custom domain `trading.arhamjain.in` (a subdomain of the user's own domain, DNS at Namecheap) points at the same Vercel project as of this round — the default `trading-ivory-alpha.vercel.app` URL still works too, Vercel serves both. Supabase Auth's **Site URL** was updated to the new subdomain (see the password-reset gotcha noted below) — if the custom domain ever changes again, that setting needs updating too, or password-reset emails silently point to the wrong place.

## Running / previewing

Nothing to build for the frontend. Open `index.html` directly in a browser, or serve the directory with any static file server (e.g. `python -m http.server`) if `file://` restrictions become an issue — note the Market Regime tab's live fetches (`/api/regime`, `/api/breadth`) only work when deployed on Vercel, since those routes are serverless functions with no local equivalent on this machine (no node/npm/Vercel CLI installed). There are no lint or test commands configured for this repo. Schema changes are applied by running SQL directly in the Supabase dashboard's SQL Editor — there is no migration runner. Any change to `api/regime.js`/`api/breadth.js` should be pushed alone and curl/fetch-tested against the live deployed URL before building UI on top of it — neither can be verified locally. `git push origin main` works directly from this sandboxed environment (Git Credential Manager's cached credential from the user's earlier interactive logins is reachable here) — no manual PowerShell round-trip needed for pushes.

## Architecture

Auth and storage are Supabase. The Supabase JS SDK is loaded via the **UMD** CDN build (not ESM), since the script is a plain non-module block and every handler is wired via inline `onclick="fn()"`, which requires `fn` to be a real global — see `.claude/skills/supabase-backend/SKILL.md` for why this matters if changing that. The client variable is named `sb`, not `supabase` — the UMD bundle itself claims `window.supabase`, so `const supabase = ...` at top level is an illegal redeclaration that silently breaks the entire script.

Top-level layout is three sibling divs toggled by `sb.auth.onAuthStateChange`: `#authgate` (email+password login/signup form — signup also asks for a Full Name, see below — plus a "Forgot password?" link), `#recoverygate` (shown on the `PASSWORD_RECOVERY` auth event — the only way to actually complete a password reset, see below), and `#app` (the actual tool, hidden until a session exists). A thin `#greeting-bar` sits directly under the topbar, inside `#app` — a time-of-day "Good Morning/Afternoon/Evening, {name}" (`renderGreeting()`, refreshed alongside the clock's 30s interval), falling back to the email's local part for accounts created before name-capture existed. Within `#app`, it's a single-page, tab-based UI with **three** views toggled by `.tab`/`.view` elements: `view-regime` (default/active tab), `view-journal`, and `view-stocks` (new this round) — switching tabs just adds/removes an `active` class, no routing. `view-journal` absorbed the former standalone Exposure tab in an earlier round — there's no `view-exposure`. There is no standalone Playbook tab either; its content (also including Capital & Leverage) lives in a wide modal (`#playbook-modal-backdrop`, opened via `openPlaybookModal()` from Journal's left panel "Playbook & Settings" row) rather than always-visible, since a 240px left panel has no comfortable room for multi-line textareas or a dozen number inputs. Each of Journal/Stocks is a `.paged-layout` (`grid-template-columns:240px 1fr`, collapsing to one column under 900px): a narrow left panel for page-specific controls, and a wide main column for the page's primary content. Market Regime **no longer has a left panel** (removed this round — its only two contents, the theme toggle and the Regime Score explanation, both moved elsewhere, see below), so `.regime-layout` gained a `.no-left` variant (`grid-template-columns:1fr 460px`, dropping the 240px track) — the main column gets the freed-up width; the right column is unchanged, a `460px` column (Market Thrust, Sector Strength, Weekly Movers, stacked) that narrows to `340px` under 1200px. Journal gets its own `.journal-layout` modifier adding a third, narrower `340px` column (Current Exposure, read-only) on the right (a `280px` variant kicks in under 1100px); Stocks gets a `.stocks-layout` modifier with a wider `320px` **left** column (news/sentiment needs more room than a typical 240px control panel), the stock table as the main column, and a `260px` **right** column (My Watchlist + its news feed, new this round) — all views collapse to one column under 900px. Several left-panel rows (Regime Score's thesis, Trade Journal) use a small collapsible-accordion pattern (`toggleSideRow(id)`, `.side-row`/`.side-body`) — click a row to expand a `-body` div directly beneath it. The Journal's "Log a Trade"/"Edit Trade" form lives in a modal (`#trade-modal-backdrop`, opened via `openTradeModal(id?)`) placed as a sibling of `main`, not nested inside `.view-journal` — a `.view{display:none}` ancestor would hide a nested `position:fixed` modal too; the Playbook and Closed Trades modals follow the same placement rule, using a `.modal-panel.wide` (900px) variant instead of the trade modal's 520px.

Dark/Light theme is a `data-theme` attribute on `<html>` (`"light"` default as of this round, previously `"dark"` — `:root[data-theme="light"]` is now the fallback rather than an override the user has to opt into), toggled by `toggleTheme()` and persisted in `localStorage` (applied on script start, before auth resolves, so there's no flash-then-switch) — reachable only from Market Regime's left panel, nowhere else in the UI, by design.

A user's **name** (captured at signup, this round) is deliberately **not** a seventh table or a column on an existing one — it's stored as Supabase auth `user_metadata` (`signUp({..., options:{data:{full_name}}})`), read back as `session.user.user_metadata.full_name`. No RLS needed (auth data is already per-user by construction), no migration needed. Accounts created before this round have no `full_name`; `renderGreeting()` falls back to the email's local part.

State lives in seven Supabase tables, each scoped to the logged-in user via Row Level Security (`auth.uid() = user_id` on select/insert/update/delete — see `supabase/schema.sql`):
- `trades` — one row per trade (the journal), server-generated UUID `id`; includes `setup` (from an editable dropdown, see `rules.setup_options`) and `market_cap` (`Large Cap`/`Mid Cap`/`Small Cap`, fixed enum)
- `rules` — one row per user, the whole playbook as columns (not key-value), plus `setup_options`/`setup_multipliers` (jsonb) driving the Journal's setup dropdown and its per-setup sizing multiplier
- `capital` — one row per user, total capital + per-segment leverage caps (`lev_equity`/`lev_fno`/`lev_indexfut`) + 6 position-sizing multiplier columns (market-cap × regime) + 3 capital-allocation-by-segment columns (`alloc_equity_pct`/`alloc_fno_pct`/`alloc_indexfut_pct`, default 50/30/20 — see the sizing note below). `Index Future` (NIFTY/BANKNIFTY/etc. futures) has its own bucket, not shared with Equity Futures — different margin/notional profile, explicit user choice. The live row also still carries old `lev_comm`/`alloc_comm_pct` values (unused since Commodity was removed as a segment; not dropped to avoid a destructive migration).
- `market_regime` — a `(user_id, snapshot_date)`-keyed history of daily market-condition snapshots, now also including `nifty500_close`/`nifty500_ema20` (the NIFTY 500 index's own daily close and incremental 20-EMA — one of the 5 Regime Score factors, seeded via `scripts/backfill_nifty500_ema20.py`). **Auto-saves** on every successful live fetch (tab-open and manual "Refresh from NSE") — this reverses an earlier deliberate no-auto-save invariant, by explicit user request (see `supabase-backend` skill's decisions log for why, and how this differs from `market_breadth_history`'s auto-save below)
- `ema_state` — one row per user holding a **jsonb map** of ~500 NIFTY 500 symbols' running EMA50/EMA200 state plus rolling `recentCloses`/`recentVolumes`/`rsCloses`/`close252` windows (not 500 rows — matches the `setup_options`-style jsonb-blob convention). `rsCloses` (66 trading days) feeds the Sector Strength panel's RS Rating drill-down; `close252` (~52 weeks, added this round) feeds the Nifty-500-scoped new-high/new-low count.
- `market_breadth_history` — a *separate* date-keyed history from `market_regime` specifically because this one **auto-updates with no click ever possible** on Market Regime tab open; also holds the 5-day-mover and volume-confirmed-mover counts (`count_up20_5d`/`count_up30_5d`/`count_up4pct_vol`/`count_down4pct_vol` — the latter two's chart was removed from the UI in an earlier round, columns/computation untouched) and, added this round, `count_newhigh_n500`/`count_newlow_n500` (Nifty-500-scoped 52-week new highs/lows, replacing an all-NSE-exchange NSE-screener count that had no history beyond ~30 days) and `count_advances`/`count_declines` (whole-market Market Thrust, a today-only snapshot stat — not backfilled historically)
- `watchlist` — one row per user, `symbols` (jsonb array of strings) — same shape as `rules.setup_options`. Feeds the Stocks tab's "My Watchlist" panel and `api/news.js`'s optional watchlist-scoped news query. Migration 007 (a fresh install picks it up automatically from `schema.sql`; an existing project needs `migration_007_watchlist.sql` run by hand).

`loadAllData()` runs after every successful sign-in, fetching most tables in parallel (`fetchTrades`/`fetchRules`/`fetchCapital`/`fetchLatestRegime`) into in-memory JS objects before the first render, then calls `onTabShown()` once for whichever tab is `.active` on load — necessary because Market Regime is now the default tab and its live fetches were originally wired only to the tab-*click* handler, which never fires for an already-active tab. On sign-out, those reset to empty defaults in memory (not just hidden), so a second account logging in on the same tab never briefly sees stale data.

Each view has a corresponding render function that rebuilds its DOM from the in-memory state on every change (no framework, no virtual DOM):
- `renderJournal()` — the Journal+Exposure tab's main render function; also calls `renderExposure()` at the end so the two stay in sync on every render (they share one tab now, no separate `onTabShown('exposure')` trigger needed). Left panel: a collapsible "Trade Journal" row (`toggleSideRow`) revealing `renderTradeBook()`'s list (all trades, open+closed, click-to-edit) only once clicked, a "Playbook & Settings" row that opens `openPlaybookModal()`, and a "Closed Trades" row that opens `openClosedTradesModal()` (its own `#closed-trades-modal-backdrop`, same pattern as Playbook — the closed-trades table's 7 columns don't fit a 240px accordion any better than Playbook's textareas did; moved out of the always-visible main column this round). Center column: stats grid (`Open Positions` / `P&L This Month`, resetting every calendar month by construction since it's a date-filtered sum, not a stored counter / `P&L This FY`, Apr–Mar Indian financial year, via `inCurrentMonth()`/`inCurrentFY()` / `Win Rate` — changed this round from the older Open/Closed/Win-Rate/Expectancy set), a compact asset-class-mix/leverage summary strip (`renderJournalSummary()`, sharing `computeExposureBySegment()` with `renderExposure()`), open positions (Instrument autocompletes via a native `<datalist>` populated from `/nifty500.json` plus a hardcoded `INDEX_SYMBOLS` array for NIFTY/BANKNIFTY/etc. index-futures instruments, segment `Index Future`) with a per-row **Edit** button opening the modal pre-filled, a **📷 Upload Screenshot** button (`openScreenshotModal()`, new this round — see the OCR note below) next to "+ Enter a Trade", and a per-trade **Size** flag (`OVERSIZED`/`undersized`/`OK`) comparing `actualRiskPct()` against `suggestedRiskPct()` (setup × market-cap × regime multipliers, see `nse-market-data` skill for the formula — `actualRiskPct()` measures risk against the trade's own segment's allocated capital via `segmentCapital()`, not 100% of total capital for every segment; a caption clarifies this is a *different* measure from Exposure's OVER CAP, not a contradiction when the two disagree). Right column: `renderExposure()` — one compact `.exposure-card` per segment (pill + OK/OVER CAP status, exposure-vs-allocated in short ₹L/Cr notation via `formatInrShort()`, leverage-used-vs-cap) rather than the original 6-column table, which was wide enough to get clipped off the right edge of this column's narrower track; read-only here, since the Capital & Leverage Caps + Position Sizing Multipliers *form* that used to sit in a standalone Exposure tab moved into the Playbook modal (see below) — one place for "how I want to trade," numbers and rules together, rather than splitting them across two tabs.
- **Screenshot upload** (`openScreenshotModal()`/`handleScreenshotUpload()`) — free, on-device OCR via the `Tesseract.js` CDN library (no API key, no cost; the user explicitly chose this over a paid vision-LLM alternative that was offered and would have been far more reliable at reading a tabular broker screenshot). `detectSymbolCandidates()` only tries to confidently match the **stock symbol** per OCR text line against `knownSymbolSet` (the same NIFTY 500 + index list backing the Instrument autocomplete) — numbers found on that line are shown as a copy-from reference, never auto-assigned to Entry/Qty/SL, since plain OCR can't reliably tell which column a number belongs to across different brokers' layouts. Clicking a detected candidate opens the normal trade modal pre-filled with just the symbol (`trade-modal-ocr-hint` shows the raw numbers found); nothing is ever saved without the user reviewing and submitting the form themselves.
- `openPlaybookModal()` — the modal now opens with **Capital & Leverage** first (Total Capital, Max Risk per Trade %, Max Leverage/Allocation/Sizing-Multiplier per segment — the same inputs/IDs the old Exposure tab had, just relocated, `loadCapitalForm()`/`saveCapital()` untouched), then **Playbook Rules** (`renderRules()`/`saveRules()`, still free-text, but trimmed from 8 fields to 6 this round — "Leverage Caps" and "Setups I Trade" were dropped since they duplicated things that now have real number/dropdown inputs right alongside; each remaining field (`ruleFields` in `index.html`) carries a one-line example hint so a first-time user isn't guessing what belongs there), then **Trade Setups & Multipliers** (`renderSetupOptions()`/`saveSetupOptions()`, unchanged).
- `renderRegimeTab()` / `renderRegimeHistory()` — **no left panel any more** (removed this round — both of its former contents relocated, see below). Main column: live-fetched tiles (VIX, FII/DII net — colored green/red with a (Buy)/(Sell) label based on sign, PCR, NIFTY 500 close — all auto-fetched, see skill) from `/api/regime`, plus New Highs/New Lows tiles now sourced from the breadth pipeline instead (Nifty-500-scoped, see below) with a small "Fetched at HH:MM" note (and the "Refresh from NSE" button beneath it) positioned to their right, `computeRegimeScore()` for a **7-factor weighted** (not equal-weighted, not this round) Risk-On (green) / Neutral (yellow) / Risk-Off (red) read on a smooth 0-100 continuum (shows "Scoring…" until every factor's data has arrived — see skill) with a small **(i) icon** next to the tile (`toggleRegimeInfo()`, new this round — replaces the old left-panel "Regime Score" accordion row) toggling `#regime-score-info-popup` open/closed right below the stat grid, a history table, and four charts (New Highs/Lows — now Nifty-500-scoped and reading from `breadthHistory` for ~4 years of depth instead of the old 30-row `regimeHistory` cap, % above 50 EMA, % above 200 EMA, Up 20%+/30%+ in 5D — the "Up/Down 4%+ on Volume" chart was removed from the UI in an earlier round, though the underlying counts are still computed/stored) via the `lightweight-charts` CDN library, cached per-container in `chartCache` so re-renders call `.setData()` rather than recreating chart instances. `updateBreadthIfNeeded()` (triggered on tab-open, not cron — see skill for why) keeps all the breadth charts current by fetching just one day's data from `/api/breadth` and applying an incremental update client-side; breadth history now spans ~4 years / 2022-06-29 to present. A third right-hand column starts with a small right-aligned **🌓 Theme** button (`toggleTheme()` — moved out of the now-gone left panel this round, the only place it's reachable) directly above the stacked panels, the top two of which are now **live** rather than waiting on the EOD bhavcopy (see `nse-market-data` skill for the new data source): `renderMarketThrust()` — a plain CSS conic-gradient pie of today's whole-market advance/decline %, preferring `liveRegime.thrustAdvances`/`thrustDeclines` (refreshed by `fetchRegimeLive()` — tab-open, "Refresh from NSE", and a ~60s auto-refresh interval that only ticks while the Market Regime tab is active) and falling back to the last saved `breadthHistory[0]` count only if live data isn't available; `renderSectorStrength()`, ranked horizontal bars now showing **% of each sector index's constituents advancing today** (`liveRegime.sectorAdvDecl`, same live source/refresh cadence as Market Thrust), falling back to the older %-above-200-EMA measure (computed from `sectors.json` + `emaStateCache`) when live data is unavailable (market closed, fetch error) — either way each row is clickable, expanding a drill-down of that sector's top 10 constituents by RS Rating (`computeRSRatings()`, an IBD-style 1–99 percentile of trailing ~3-month return against the tracked universe, still `ema_state`-derived — unaffected by the live-source switch) with an F&O badge sourced from the best-effort `fo_universe.json`; and `renderWeeklyMovers()` — a small table of the best/worst 2 **sectors** (not individual stocks, changed this round) by average constituent trailing 5-trading-day return, for each of the last 3 weeks, computed via `computeWeeklySectorMovers()` by slicing `emaStateCache`'s existing `rsCloses` window in 5-day chunks from the end, grouped by `sectorsData`'s constituent lists — no new data fetched or stored, purely a different read of the same RS-Rating window. `computeRegimeScore()`'s inputs are assembled once in `gatherRegimeScoreInputs()` (shared by this tab, `autoSaveRegimeSnapshot()`, and the Stocks tab's Fear/Greed gauge below) rather than duplicated per call site, and `emaStateCache`'s lazy-load is likewise shared via `ensureEmaStateCache()`.
- `view-stocks` — left column stacks three panels, populated by `onTabShown('stocks')` (which also triggers `fetchRegimeLive()`/`updateBreadthIfNeeded()` itself, so this tab works standalone even if Market Regime was never visited): `renderFearGreed()` — **not a separate model**, just the same `computeRegimeScore()` composite relabeled with the classic 5-band Fear/Greed framing (Extreme Fear → Extreme Greed), because Google Trends has no reliable free finance-sentiment API (confirmed this round — see `nse-market-data` skill); `renderNewsPanel()`/`renderTrendingPanel()` — India + world markets headlines and a generic trending-searches widget, both from `/api/news.js` (`fetchNews()`, tab-open only, no auto-refresh — a news feed doesn't need one), with external content escaped (`escapeHtml()`) and links protocol-checked (`isHttpUrl()`) before rendering, since feed content is untrusted input. Main column: `renderStockTable()` — a scrollable table of all ~500 tracked NIFTY 500 symbols (Name, Market Cap from `marketcap.json`, RS Score from `computeRSRatings()`, and volume deviation from `volumeDeviationPct()` — today's `ema_state` `recentVolumes` entry vs. the average of the 5 trading days just before it), sorted by RS Score descending, entirely client-side from data already tracked for other panels. Right column (new this round): **My Watchlist** — add/remove symbols (`addToWatchlist()`/`removeFromWatchlist()`, backed by the `watchlist` table, autocompleted via the same `#instrument-list` datalist as the trade form) and a dedicated **Watchlist News** panel (`renderWatchlistNews()`) scoped to just those symbols via `api/news.js`'s `?watchlist=` param — `fetchNews()` includes it automatically whenever `watchlist` is non-empty, and re-fetches immediately on add/remove rather than waiting for the next tab-open.

Regime/breadth data also auto-refreshes once per day **at market open (9:15 AM IST)** regardless of which tab is active (`maybeAutoRefreshAtMarketOpen()`, checked every 60s alongside the existing while-tab-active interval) — so data is current by the time the user checks Regime/Stocks even if they were parked on Journal when the market opened. This is *not* a real background job: it only fires while some browser tab has the app open (no cron, no `service_role` — same constraint as everywhere else in this app), it just closes the specific gap of "tab open but on a different view when 9:15 passes."

Data flow: a UI action is `async`, hits Supabase directly (insert/update/delete/upsert), then patches the in-memory object and calls the relevant `render*()` — no framework reactivity. `rules`/`capital` writes use `upsert` (one-row-per-user, new users have no row yet); date-keyed tables upsert on their `(user_id, snapshot_date)` unique constraint so re-saving the same day overwrites rather than duplicating. `addTrade()` branches on a module-level `editingTradeId` set by `openTradeModal(id)`: present → `update().eq('id', ...)` and patch the existing array entry in place; absent → the original insert path. JS objects are camelCase; Postgres columns are snake_case — no auto-mapping, every call site translates by hand (see `supabase-backend` skill for the exact mappings). **`saveRules()` builds an explicit payload of only the free-text rule fields** rather than spreading the whole `rules` object — `rules` also holds `setupOptions`/`setupMultipliers` (camelCase, no matching DB column), and spreading it would send Supabase invalid keys.

Trade `segment` values (`Equity Cash`, `Equity Futures`, `Index Future` — simplified from 5 to 3 this round; `F&O - Options`/`Commodity` removed after confirming zero live trades used either) drive both the color-coded `.pill` styling (`segClass()`) and which leverage cap and allocation slice in `capital` applies in the exposure view (`segmentCapital(segment) = capital.total × allocPct[segment]/100`, shared by Exposure and Journal). Trade `market_cap` and `setup` separately drive the position-sizing suggestion in the Journal.

`SUPABASE_URL`/`SUPABASE_ANON_KEY` are embedded directly in `index.html` — intentional, since the anon key is meant to be public and RLS is what actually enforces per-user isolation. The `service_role` key must never appear anywhere in this repo, including `api/regime.js`/`api/breadth.js` — both are pure read-only NSE proxies (browser can't call NSE directly: CORS + bot-protection) and never touch Supabase at all; every write happens client-side, authenticated as the user, same as every other table. The one-time EMA-breadth historical backfill (`scripts/backfill_ema.py`) follows the same rule — it computes offline with no Supabase access at all, and its output is persisted afterward via an already-authenticated browser session, never a stored credential.

Password reset needs both the Supabase dashboard's Auth **Site URL** pointed at the deployed Vercel URL (not `localhost` — a real gotcha hit once, emailed links silently pointed to `localhost` until fixed in Authentication → URL Configuration) *and* the `#recoverygate` UI in `index.html` — Supabase's recovery link alone only establishes a session, it does **not** prompt for a new password; without a UI to call `sb.auth.updateUser({password})`, a user could be "logged in" via the recovery link yet never actually manage to change their password.
