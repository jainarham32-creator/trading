# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

The frontend is a single self-contained file: [index.html](index.html). It is "Market Terminal" (renamed from "Trading Desk" this round), a web app for logging trades, defining a personal trading playbook, tracking capital/leverage exposure, reading a live market-regime dashboard with charts, and getting a position-sizing sanity check — backed by Supabase (Postgres + Auth) for storage/login and two Vercel serverless functions (`api/regime.js`, `api/breadth.js`) for live market data. There is no build system for the frontend, no test suite — all HTML/CSS/JS lives inline in `index.html`. Other files: `nifty500.json` (static NIFTY 500 constituent list for the Journal's instrument autocomplete, refreshed manually/quarterly), `sectors.json` (static sector-name → constituent-symbols map for 14 confirmed NSE sector indices, same manual-refresh convention — feeds the Sector Strength panel's RS Rating drill-down and its %-above-200-EMA fallback; the panel's primary live number now comes straight from `api/regime.js`, see below), `fo_universe.json` (static, best-effort list of F&O-eligible symbols — no live-verifiable NSE source found for this one, compiled from general knowledge, badges the Sector Strength drill-down's F&O names), `scripts/backfill_ema.py` + its committed output `scripts/ema_backfill_*.json` (one-time offline EMA-breadth computation, not run automatically), `scripts/backfill_nifty500_ema20.py` + `scripts/nifty500_ema20_*.json` (same idea, one series — the NIFTY 500 index's own 20-EMA), `supabase/schema.sql` (fresh-install DB baseline) + `supabase/migration_*.sql` (incremental, additive changes actually run against the live project — run by hand in the Supabase SQL Editor), `package.json` (pins `engines.node` for Vercel's build of the `api/` functions — no dependencies), and two skills: `.claude/skills/supabase-backend/SKILL.md` (Supabase/RLS/auth conventions — read before touching auth or adding a table) and `.claude/skills/nse-market-data/SKILL.md` (which NSE endpoints actually work, the regime-scoring/EMA-breadth/position-sizing formulas — read before touching either `api/*.js` function or the Market Regime tab).

Deployed on Vercel, auto-deploying from `main` on `github.com/jainarham32-creator/trading`.

## Running / previewing

Nothing to build for the frontend. Open `index.html` directly in a browser, or serve the directory with any static file server (e.g. `python -m http.server`) if `file://` restrictions become an issue — note the Market Regime tab's live fetches (`/api/regime`, `/api/breadth`) only work when deployed on Vercel, since those routes are serverless functions with no local equivalent on this machine (no node/npm/Vercel CLI installed). There are no lint or test commands configured for this repo. Schema changes are applied by running SQL directly in the Supabase dashboard's SQL Editor — there is no migration runner. Any change to `api/regime.js`/`api/breadth.js` should be pushed alone and curl/fetch-tested against the live deployed URL before building UI on top of it — neither can be verified locally. `git push origin main` works directly from this sandboxed environment (Git Credential Manager's cached credential from the user's earlier interactive logins is reachable here) — no manual PowerShell round-trip needed for pushes.

## Architecture

Auth and storage are Supabase. The Supabase JS SDK is loaded via the **UMD** CDN build (not ESM), since the script is a plain non-module block and every handler is wired via inline `onclick="fn()"`, which requires `fn` to be a real global — see `.claude/skills/supabase-backend/SKILL.md` for why this matters if changing that. The client variable is named `sb`, not `supabase` — the UMD bundle itself claims `window.supabase`, so `const supabase = ...` at top level is an illegal redeclaration that silently breaks the entire script.

Top-level layout is three sibling divs toggled by `sb.auth.onAuthStateChange`: `#authgate` (email+password login/signup form, plus a "Forgot password?" link), `#recoverygate` (shown on the `PASSWORD_RECOVERY` auth event — the only way to actually complete a password reset, see below), and `#app` (the actual tool, hidden until a session exists). Within `#app`, it's a single-page, tab-based UI with **two** views toggled by `.tab`/`.view` elements: `view-regime` (default/active tab) and `view-journal` — switching tabs just adds/removes an `active` class, no routing. `view-journal` absorbed the former standalone Exposure tab this round (see below) — there's no `view-exposure` any more. There is no standalone Playbook tab either; its content (now also including Capital & Leverage, see below) lives in a wide modal (`#playbook-modal-backdrop`, opened via `openPlaybookModal()` from Journal's left panel "Playbook & Settings" row) rather than always-visible, since a 240px left panel has no comfortable room for multi-line textareas or a dozen number inputs. Each of the two views is a `.paged-layout` (`grid-template-columns:240px 1fr`, collapsing to one column under 900px): a narrow left panel for page-specific controls, and a wide main column for the page's primary content. Market Regime additionally gets a page-scoped `.regime-layout` modifier adding a third `460px` column (Market Thrust + Sector Strength, stacked) on the right (a `340px` variant kicks in under 1200px); Journal gets its own `.journal-layout` modifier adding a third, narrower `340px` column (Current Exposure, read-only — its editable Capital & Leverage form moved into the Playbook modal, see below) on the right (a `280px` variant kicks in under 1100px) — both collapse to one column under 900px. Several left-panel rows (Regime Score's thesis, Trade Journal) use a small collapsible-accordion pattern (`toggleSideRow(id)`, `.side-row`/`.side-body`) — click a row to expand a `-body` div directly beneath it. The Journal's "Log a Trade"/"Edit Trade" form lives in a modal (`#trade-modal-backdrop`, opened via `openTradeModal(id?)`) placed as a sibling of `main`, not nested inside `.view-journal` — a `.view{display:none}` ancestor would hide a nested `position:fixed` modal too; the Playbook modal follows the same placement rule, using a `.modal-panel.wide` (900px) variant instead of the trade modal's 520px.

Dark/Light theme is a `data-theme` attribute on `<html>` (`"light"` default as of this round, previously `"dark"` — `:root[data-theme="light"]` is now the fallback rather than an override the user has to opt into), toggled by `toggleTheme()` and persisted in `localStorage` (applied on script start, before auth resolves, so there's no flash-then-switch) — reachable only from Market Regime's left panel, nowhere else in the UI, by design.

State lives in six Supabase tables, each scoped to the logged-in user via Row Level Security (`auth.uid() = user_id` on select/insert/update/delete — see `supabase/schema.sql`):
- `trades` — one row per trade (the journal), server-generated UUID `id`; includes `setup` (from an editable dropdown, see `rules.setup_options`) and `market_cap` (`Large Cap`/`Mid Cap`/`Small Cap`, fixed enum)
- `rules` — one row per user, the whole playbook as columns (not key-value), plus `setup_options`/`setup_multipliers` (jsonb) driving the Journal's setup dropdown and its per-setup sizing multiplier
- `capital` — one row per user, total capital + per-segment leverage caps (`lev_equity`/`lev_fno`/`lev_indexfut`) + 6 position-sizing multiplier columns (market-cap × regime) + 3 capital-allocation-by-segment columns (`alloc_equity_pct`/`alloc_fno_pct`/`alloc_indexfut_pct`, default 50/30/20 — see the sizing note below). `Index Future` (NIFTY/BANKNIFTY/etc. futures) has its own bucket, not shared with Equity Futures — different margin/notional profile, explicit user choice. The live row also still carries old `lev_comm`/`alloc_comm_pct` values (unused since Commodity was removed as a segment; not dropped to avoid a destructive migration).
- `market_regime` — a `(user_id, snapshot_date)`-keyed history of daily market-condition snapshots, now also including `nifty500_close`/`nifty500_ema20` (the NIFTY 500 index's own daily close and incremental 20-EMA — one of the 5 Regime Score factors, seeded via `scripts/backfill_nifty500_ema20.py`). **Auto-saves** on every successful live fetch (tab-open and manual "Refresh from NSE") — this reverses an earlier deliberate no-auto-save invariant, by explicit user request (see `supabase-backend` skill's decisions log for why, and how this differs from `market_breadth_history`'s auto-save below)
- `ema_state` — one row per user holding a **jsonb map** of ~500 NIFTY 500 symbols' running EMA50/EMA200 state plus rolling `recentCloses`/`recentVolumes`/`rsCloses`/`close252` windows (not 500 rows — matches the `setup_options`-style jsonb-blob convention). `rsCloses` (66 trading days) feeds the Sector Strength panel's RS Rating drill-down; `close252` (~52 weeks, added this round) feeds the Nifty-500-scoped new-high/new-low count.
- `market_breadth_history` — a *separate* date-keyed history from `market_regime` specifically because this one **auto-updates with no click ever possible** on Market Regime tab open; also holds the 5-day-mover and volume-confirmed-mover counts (`count_up20_5d`/`count_up30_5d`/`count_up4pct_vol`/`count_down4pct_vol` — the latter two's chart was removed from the UI in an earlier round, columns/computation untouched) and, added this round, `count_newhigh_n500`/`count_newlow_n500` (Nifty-500-scoped 52-week new highs/lows, replacing an all-NSE-exchange NSE-screener count that had no history beyond ~30 days) and `count_advances`/`count_declines` (whole-market Market Thrust, a today-only snapshot stat — not backfilled historically)

`loadAllData()` runs after every successful sign-in, fetching most tables in parallel (`fetchTrades`/`fetchRules`/`fetchCapital`/`fetchLatestRegime`) into in-memory JS objects before the first render, then calls `onTabShown()` once for whichever tab is `.active` on load — necessary because Market Regime is now the default tab and its live fetches were originally wired only to the tab-*click* handler, which never fires for an already-active tab. On sign-out, those reset to empty defaults in memory (not just hidden), so a second account logging in on the same tab never briefly sees stale data.

Each view has a corresponding render function that rebuilds its DOM from the in-memory state on every change (no framework, no virtual DOM):
- `renderJournal()` — the Journal+Exposure tab's main render function; also calls `renderExposure()` at the end so the two stay in sync on every render (they share one tab now, no separate `onTabShown('exposure')` trigger needed). Left panel: a collapsible "Trade Journal" row (`toggleSideRow`) revealing `renderTradeBook()`'s list (all trades, open+closed, click-to-edit) only once clicked, a "Playbook & Settings" row that opens `openPlaybookModal()`, and a "Closed Trades" row that opens `openClosedTradesModal()` (its own `#closed-trades-modal-backdrop`, same pattern as Playbook — the closed-trades table's 7 columns don't fit a 240px accordion any better than Playbook's textareas did; moved out of the always-visible main column this round). Center column: stats grid, a compact asset-class-mix/leverage summary strip (`renderJournalSummary()`, sharing `computeExposureBySegment()` with `renderExposure()`), open positions (Instrument autocompletes via a native `<datalist>` populated from `/nifty500.json` plus a hardcoded `INDEX_SYMBOLS` array for NIFTY/BANKNIFTY/etc. index-futures instruments, segment `Index Future`) with a per-row **Edit** button opening the modal pre-filled, and a per-trade **Size** flag (`OVERSIZED`/`undersized`/`OK`) comparing `actualRiskPct()` against `suggestedRiskPct()` (setup × market-cap × regime multipliers, see `nse-market-data` skill for the formula — `actualRiskPct()` measures risk against the trade's own segment's allocated capital via `segmentCapital()`, not 100% of total capital for every segment; a caption clarifies this is a *different* measure from Exposure's OVER CAP, not a contradiction when the two disagree). Right column: `renderExposure()` — one compact `.exposure-card` per segment (pill + OK/OVER CAP status, exposure-vs-allocated in short ₹L/Cr notation via `formatInrShort()`, leverage-used-vs-cap) rather than the original 6-column table, which was wide enough to get clipped off the right edge of this column's narrower track; read-only here, since the Capital & Leverage Caps + Position Sizing Multipliers *form* that used to sit in a standalone Exposure tab moved into the Playbook modal (see below) — one place for "how I want to trade," numbers and rules together, rather than splitting them across two tabs.
- `openPlaybookModal()` — the modal now opens with **Capital & Leverage** first (Total Capital, Max Risk per Trade %, Max Leverage/Allocation/Sizing-Multiplier per segment — the same inputs/IDs the old Exposure tab had, just relocated, `loadCapitalForm()`/`saveCapital()` untouched), then **Playbook Rules** (`renderRules()`/`saveRules()`, still free-text, but trimmed from 8 fields to 6 this round — "Leverage Caps" and "Setups I Trade" were dropped since they duplicated things that now have real number/dropdown inputs right alongside; each remaining field (`ruleFields` in `index.html`) carries a one-line example hint so a first-time user isn't guessing what belongs there), then **Trade Setups & Multipliers** (`renderSetupOptions()`/`saveSetupOptions()`, unchanged).
- `renderRegimeTab()` / `renderRegimeHistory()` — left panel: the Dark/Light toggle, plus a collapsible "Regime Score" row explaining the scoring thesis/weighting. Main column: live-fetched tiles (VIX, FII/DII net — colored green/red with a (Buy)/(Sell) label based on sign, PCR, NIFTY 500 close — all auto-fetched, see skill) from `/api/regime`, plus New Highs/New Lows tiles now sourced from the breadth pipeline instead (Nifty-500-scoped, see below) with a small "Fetched at HH:MM" note (and the "Refresh from NSE" button beneath it) positioned to their right, `computeRegimeScore()` for a **7-factor weighted** (not equal-weighted, not this round) Risk-On (green) / Neutral (yellow) / Risk-Off (red) read on a smooth 0-100 continuum (shows "Scoring…" until every factor's data has arrived — see skill), a history table, and four charts (New Highs/Lows — now Nifty-500-scoped and reading from `breadthHistory` for ~4 years of depth instead of the old 30-row `regimeHistory` cap, % above 50 EMA, % above 200 EMA, Up 20%+/30%+ in 5D — the "Up/Down 4%+ on Volume" chart was removed from the UI in an earlier round, though the underlying counts are still computed/stored) via the `lightweight-charts` CDN library, cached per-container in `chartCache` so re-renders call `.setData()` rather than recreating chart instances. `updateBreadthIfNeeded()` (triggered on tab-open, not cron — see skill for why) keeps all the breadth charts current by fetching just one day's data from `/api/breadth` and applying an incremental update client-side; breadth history now spans ~4 years / 2022-06-29 to present. A third right-hand column stacks three panels, the top two now **live** rather than waiting on the EOD bhavcopy (see `nse-market-data` skill for the new data source): `renderMarketThrust()` — a plain CSS conic-gradient pie of today's whole-market advance/decline %, preferring `liveRegime.thrustAdvances`/`thrustDeclines` (refreshed by `fetchRegimeLive()` — tab-open, "Refresh from NSE", and a ~60s auto-refresh interval that only ticks while the Market Regime tab is active) and falling back to the last saved `breadthHistory[0]` count only if live data isn't available; `renderSectorStrength()`, ranked horizontal bars now showing **% of each sector index's constituents advancing today** (`liveRegime.sectorAdvDecl`, same live source/refresh cadence as Market Thrust), falling back to the older %-above-200-EMA measure (computed from `sectors.json` + `emaStateCache`) when live data is unavailable (market closed, fetch error) — either way each row is clickable, expanding a drill-down of that sector's top 10 constituents by RS Rating (`computeRSRatings()`, an IBD-style 1–99 percentile of trailing ~3-month return against the tracked universe, still `ema_state`-derived — unaffected by the live-source switch) with an F&O badge sourced from the best-effort `fo_universe.json`; and `renderWeeklyMovers()` (new this round) — a small table of the best/worst 2 NIFTY 500 names by trailing 5-trading-day return, for each of the last 3 weeks, computed via `computeWeeklyTopMovers()` by slicing `emaStateCache`'s existing `rsCloses` window in 5-day chunks from the end — no new data fetched or stored, purely a different read of the same RS-Rating window.

Data flow: a UI action is `async`, hits Supabase directly (insert/update/delete/upsert), then patches the in-memory object and calls the relevant `render*()` — no framework reactivity. `rules`/`capital` writes use `upsert` (one-row-per-user, new users have no row yet); date-keyed tables upsert on their `(user_id, snapshot_date)` unique constraint so re-saving the same day overwrites rather than duplicating. `addTrade()` branches on a module-level `editingTradeId` set by `openTradeModal(id)`: present → `update().eq('id', ...)` and patch the existing array entry in place; absent → the original insert path. JS objects are camelCase; Postgres columns are snake_case — no auto-mapping, every call site translates by hand (see `supabase-backend` skill for the exact mappings). **`saveRules()` builds an explicit payload of only the free-text rule fields** rather than spreading the whole `rules` object — `rules` also holds `setupOptions`/`setupMultipliers` (camelCase, no matching DB column), and spreading it would send Supabase invalid keys.

Trade `segment` values (`Equity Cash`, `Equity Futures`, `Index Future` — simplified from 5 to 3 this round; `F&O - Options`/`Commodity` removed after confirming zero live trades used either) drive both the color-coded `.pill` styling (`segClass()`) and which leverage cap and allocation slice in `capital` applies in the exposure view (`segmentCapital(segment) = capital.total × allocPct[segment]/100`, shared by Exposure and Journal). Trade `market_cap` and `setup` separately drive the position-sizing suggestion in the Journal.

`SUPABASE_URL`/`SUPABASE_ANON_KEY` are embedded directly in `index.html` — intentional, since the anon key is meant to be public and RLS is what actually enforces per-user isolation. The `service_role` key must never appear anywhere in this repo, including `api/regime.js`/`api/breadth.js` — both are pure read-only NSE proxies (browser can't call NSE directly: CORS + bot-protection) and never touch Supabase at all; every write happens client-side, authenticated as the user, same as every other table. The one-time EMA-breadth historical backfill (`scripts/backfill_ema.py`) follows the same rule — it computes offline with no Supabase access at all, and its output is persisted afterward via an already-authenticated browser session, never a stored credential.

Password reset needs both the Supabase dashboard's Auth **Site URL** pointed at the deployed Vercel URL (not `localhost` — a real gotcha hit once, emailed links silently pointed to `localhost` until fixed in Authentication → URL Configuration) *and* the `#recoverygate` UI in `index.html` — Supabase's recovery link alone only establishes a session, it does **not** prompt for a new password; without a UI to call `sb.auth.updateUser({password})`, a user could be "logged in" via the recovery link yet never actually manage to change their password.
